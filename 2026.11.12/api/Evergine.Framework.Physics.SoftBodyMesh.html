    public class SoftBodyMesh : MeshComponent, IDependencyObject
    Remarks

    This is the shape half of a soft body: it says what the thing is -- a cloth, a sphere, a torus, a model from the project -- while SoftBody says how it behaves. The same split the engine already makes between a cube mesh and a BoxCollider, and the reason the pair reads as an ordinary visible entity: material, mesh, renderer.

    It is a mesh and not a renderer, which is why it is not called one. A primitive mesh would not do: changing a primitive's geometry rebuilds the whole model and its GPU buffers, and a soft body moves every vertex every step. This owns a dynamic mesh instead and rewrites its position and normal buffers in place as the simulation hands over new vertices.

    The geometry exists as soon as the component is attached, with no physics involved, so the shape can be seen and picked in the editor before anything simulates. On its own, without a SoftBody beside it, this is simply a procedural mesh that never moves.

    Remarks

    A model is not obliged to be modelled around its own origin, and plenty are not: the duck of the glTF sample set sits eighty-seven units above it. That offset matters more here than it does for a rendered model, because the origin of the entity is what the gizmo drags and what the solver uses as the position of the body, and a body whose origin falls outside its own surface is awkward to place and stranger still to rotate.

    WeldDistance

    Gets or sets how close two vertices have to be before they are treated as one.

    Declaration
    [RenderPropertyAsFInput(MinLimit = 0, ShowConditionFunction = "UsesWelding", Tooltip = "How close two vertices have to be before they count as one, which is what stitches a model's seams.")]
public float WeldDistance { get; set; }
    Property Value
    Type Description
    float
    Remarks

    Rendering meshes split vertices wherever a normal or a texture coordinate changes, so a model's seams arrive as pairs of vertices sitting on top of each other. Simulated as they are, the surface tears along every seam, because nothing connects the two halves. Welding stitches them back together. Only the simulated copy is welded: the drawn one keeps its split vertices and the texture coordinates that go with them, so closing a seam for the solver costs nothing on screen.

    Only models need it. The generated shapes repeat their seams by exactly zero distance and are always joined on that alone.
