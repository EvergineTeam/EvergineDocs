    public class PhysicsManager : UpdatableSceneManager, IDependencyObject
    Remarks

    Constraints capture the poses of the bodies they hold, so they can only be created once those bodies are in the world. Adding one is therefore deferred like every other structural change, and retried on the following frame while the bodies it needs are still pending.

    MaxBodyPairs

public uint MaxBodyPairs { get; set; }
    Property Value
    Type Description
    uint
    Remarks

    A pair is two bodies close enough to be worth looking at in detail, so this grows with how crowded the world gets rather than with how many bodies it holds. Something like eight per body is a reasonable start for a pile; running out of them is reported by the step and drops collisions on the floor.

    MaxContactConstraints

    Gets or sets the maximum number of contact constraints solved per step. Only read when the world is created.

    Declaration

public uint MaxContactConstraints { get; set; }
    Property Value
    Type Description
    uint
    Remarks

    This is the one that runs out first in a heap of bodies: a box resting in a pile touches three or four others, so a few thousand bodies settling on each other need tens of thousands of these. When they run out the step says so and the contacts that did not fit are simply not solved, which looks like bodies sinking into each other for no reason.

    FlushPending()

    Applies every pending structural change, such as bodies waiting to enter or leave the world.

    Declaration
    public void FlushPending()
    Remarks

    Structural changes are deferred so they never happen while the simulation is running, and so that several edits on the same frame collapse into a single operation. Call this when a query must observe a body that was created in the very same frame.

    This only applies what has already been queued, and a body queues itself when its component is activated. Entities added from CreateScene are not activated until the scene finishes initializing, so calling this from there flushes nothing and the world is still empty: queries that need those bodies belong in the first update, not in scene creation.

    Event Type
    Type Description
    EventHandler<RigidBody>
    Remarks

    Raised on the main thread once the step is over, not from inside the simulation, so it is safe to touch the scene from here. A body counts as awake the moment the simulation starts spending time on it, which is what makes this worth listening to: it is the cheap way to notice something has been disturbed without asking every body every frame whether it is still still.
