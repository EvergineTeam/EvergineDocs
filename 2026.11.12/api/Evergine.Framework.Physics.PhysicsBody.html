    Syntax
    public abstract class PhysicsBody : Component, IDependencyObject
    Remarks

    This holds everything a body needs regardless of whether it moves: the shape built from the Collider components found on this entity and its descendants, the transform synchronization with the simulation, and the collision events. RigidBody adds the motion related settings and behavior on top of this, and StaticBody adds nothing, since a static body has no motion to speak of.

    Every property can be set before the entity is activated: values are kept in the component and pushed to the simulation when the body is created.

    InvalidateShape()

    Rebuilds the shape of this body from its colliders.

    Declaration
    public void InvalidateShape()
    Remarks

    The rebuild happens here and now, not on the next step. Waiting for the step would mean a body whose collider or scale changed keeps the shape it was built with for as long as the simulation is not running, and the editor runs its picking world with the simulation off: gizmo handles are rescaled every frame to hold their size on screen, so their pickable shape would freeze at whatever size it had when the body was created and clicks would land nowhere near what is drawn. A body that does not exist yet has nothing to rebuild, and gets its shape built when it joins the world.

    CollisionStarted

    Raised on the first step two bodies touch. Sensors raise it too, which is how triggers are built.

    Declaration
    public event EventHandler<CollisionInfo> CollisionStarted
    Event Type
    Type Description
    EventHandler<CollisionInfo>
    Remarks

    Contacts are detected on worker threads and dispatched here after the step, on the main thread, so the scene can be touched safely from the handler. A body with several colliders raises the event once per pair of bodies, not once per pair of shapes.
